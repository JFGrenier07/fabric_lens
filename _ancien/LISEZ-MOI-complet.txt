FABRIC LENS — installation
================================================================================

CE QU'IL FAUT AVOIR
--------------------------------------------------------------------------------
  Sur ton poste Windows   plink.exe et pscp.exe (PuTTY), et ta session PuTTY
                          Kerberos qui fonctionne deja.
                          PAS de Python. PAS de serveur. PAS de droits admin.

  Sur la RHEL             python3 (3.6 ou plus recent) et l'acces en lecture
                          aux backups. Rien a installer : le .bat y depose
                          les scripts a chaque execution.


OU L'INSTALLER
--------------------------------------------------------------------------------
  Copie le dossier FabricLens ou tu veux sur ton poste Windows. Par exemple :

      C:\Users\<toi>\Documents\FabricLens

  Ne separe pas les sous-dossiers : le .bat les cherche a cote de lui.

      FabricLens\
        scripts\fabric-lens-fetch.bat     <- ce que tu lances
        scripts\remote\fl_extract.py      <- LE FICHIER A EDITER
        fabriclens\                       <- resolveur + assembleur
        web\                              <- modules JS + gabarit
        data\                             <- l'application y atterrira


CE QU'IL FAUT REGLER — DEUX ENDROITS, PAS UN DE PLUS
--------------------------------------------------------------------------------
  1) scripts\fabric-lens-fetch.bat, tout en haut :

         set "PUTTY_SESSION=RHEL-BACKUPS"

     Mets le nom EXACT de ta session PuTTY.

  2) scripts\remote\fl_extract.py, le bloc FABRICS en tete :

         FABRICS = [
             ("DC-PARIS-01",  "/data/backups/aci/paris"),
             ("DC-LYON-02",   "/data/backups/aci/lyon"),
             ...  une ligne par fabrique
         ]

     Le premier element est le nom affiche dans l'application.
     Le second est un repertoire, un motif (ce2_*.tar.gz), ou un chemin
     relatif. Le backup le PLUS RECENT est pris automatiquement.

     Tu edites ce fichier ici, cote Windows. Le .bat le renvoie sur la RHEL
     a chaque execution : rien a maintenir des deux cotes.


COMMENT LE LANCER
--------------------------------------------------------------------------------
  Premiere fois — mode test, qui ne touche a rien :

      scripts\fabric-lens-fetch.bat test

  Il verifie la connexion, teste l'extracteur sur la RHEL, et liste les
  backups qu'il a reperes. Aucune archive ouverte, rien ecrit, rien
  telecharge. Si la liste des fabriques est juste, tu es pret.

  Ensuite, chaque matin :

      scripts\fabric-lens-fetch.bat

  Puis double-clique :

      data\fabric-lens.html

  C'est tout. L'application fonctionne hors ligne, sans reseau, sans serveur.


SI QUELQUE CHOSE CLOCHE
--------------------------------------------------------------------------------
  plink.exe introuvable          PuTTY hors du PATH : renseigne PUTTY_DIR
                                 en tete du .bat.

  connexion impossible           Nom de session inexact, ou ticket Kerberos
                                 expire. Verifie avec  klist

  aucun backup repere            Les chemins du bloc FABRICS n'existent pas
                                 sur la RHEL. Verifie-en un a la main :
                                 ls -l /data/backups/aci/paris

  classes UTILES sans gabarit    Tes fabriques contiennent une construction
                                 ACI que le labo n'avait pas. Ce n'est pas
                                 grave, mais transmets-moi ces lignes :
                                 c'est exactement ce qu'il me faut pour
                                 completer l'extracteur.

  Dans tous les cas, le .bat s'arrete au premier probleme et ne modifie
  rien localement.


CE QUE L'APPLICATION AFFICHE EN BAS A DROITE
--------------------------------------------------------------------------------
      build 2026-07-21 14:35 · 37a43e · verifie 2314/2314

  Le premier bloc identifie la version : si tu ne le vois pas changer apres
  un nouveau run, tu regardes une vieille copie (Ctrl+Shift+R).

  Le second est l'auto-verification : le resolveur JavaScript rejoue toutes
  les recherches possibles et compare ses reponses a celles du resolveur
  Python, calculees sur la RHEL. Ce controle tourne ENTIEREMENT chez toi,
  sur tes donnees, et rien n'en sort. S'il affiche un ecart, ne fais pas
  confiance a l'ecran et signale-le.
